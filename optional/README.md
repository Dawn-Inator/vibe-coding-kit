# Optional Components

Optional components extend the Kit for projects that need them. Their registry is [`catalog.json`](catalog.json); the Kit installer reads that catalog to resolve the categories below. New installs leave optional categories off by default. Project settings live in `.vibe-coding/project.config.json` under `optional` and do not override project-specific policies.

The directory tree groups sources by physical type:

```text
optional/
├── catalog.json
└── skills/
    ├── aliyun-skill-discovery/
    ├── app-store-compliance/
    ├── hyperframes/
    ├── lark/
    └── presentations/
```

`catalog.json` maps the installation-purpose categories to these sources: `aliyun` and `lark` to their skill components, `non-code` to both `hyperframes` and `presentations`, and `app-store-compliance` to its audit skill.

Choose categories during a new interactive install, or pass repeated flags in scripted installs:

```sh
vibe-coding-kit install --project-root . --identity-name 'Your Project AI' --identity-email 'ai@example.org' \
  --optional aliyun=off --optional lark=on --optional non-code=off \
  --optional app-store-compliance=off
```

For an initialized project, set a category explicitly with:

```sh
node .vibe-coding/kit/cli.mjs optional configure --project-root . --optional lark=on
```

Only selected components are projected or installed. Enabling a component does not log in to an account, provision a repository or cloud resource, or create project-specific policy. Missing or unsupported component setup is reported as such. Disabling a category removes only Kit-generated mirrors and routes; project-owned files, history, credentials, and custom skill content remain under project ownership. Existing explicit preferences are retained. For legacy projects without `optional` preferences, Kit detects already-selected optional skill sources and preserves their skill decisions and pack layout when first saving preferences. For example, if only `animated-presentations` was selected, enabling `aliyun` preserves that skill without expanding the whole `non-code` bundle; explicitly enabling `non-code` later adds its full skill set while preserving user exclusions and local or replacement overrides. Only exclusions generated by the Kit migration are cleared when their category is explicitly enabled. File conflicts are preserved and reported for review.

For a registered project, ordinary `install` checks the pinned Kit and current projections. Passing `--optional <group>=on|off` explicitly updates the category preferences and selected projections. Add `--check` to preview the proposed preferences without writing config or installing the components. `optional configure --check --optional <group>=on|off` provides the same read-only preview for an initialized project.

## Categories

| Category | Components | Use |
| --- | --- | --- |
| `aliyun` | `aliyun-skill-discovery` | Discover applicable Alibaba Cloud skills for a project. |
| `lark` | `lark` | Use the Lark skill entry point and its documented operations. |
| `non-code` | `hyperframes`, `presentations` | Add the HyperFrames video workflow and presentation authoring guidance. |
| `app-store-compliance` | `app-store-compliance` | Review iOS and Android submission evidence against current official store policies. |

The retired `task-progress` preference in older project configurations is accepted and ignored. Kit no longer installs or reuses the Task Progress plugin. The shared task-storage and Heartbeat APIs remain available.

## Presentation authoring

The optional `non-code` category includes one presentation entry point, `animated-presentations`. It bundles Frontend Slides’ 12 base styles, 34 progressively loaded bold design recipes, a fixed-stage HTML starter, and optional PPTX extraction, PDF export, and publishing helpers. It retains Kit’s motion and browser-verification guidance; no separate `frontend-slides` skill/plugin is installed.

Enabling this category installs the resources, not Python packages, browsers, hosting CLI tools, or credentials. Viewable HTML needs no build step. PPTX extraction and PDF export have operation-specific dependencies; publication requires an explicit user request. See the [presentation skill](skills/presentations/skills/animated-presentations/SKILL.md) and its [tool usage](skills/presentations/skills/animated-presentations/references/tools.md).

## App store submission review

The optional `app-store-compliance` category installs one Kit-authored [audit skill](skills/app-store-compliance/skills/app-store-compliance/SKILL.md). Enable it for an initialized project with:

```sh
node .vibe-coding/kit/cli.mjs optional configure --project-root . --optional app-store-compliance=on
```

Use `$app-store-compliance` for a submission review or rejection fix plan. The skill supports a manual evidence review using current official Apple and Google policies. It links to a fixed revision of [mjmirza/app-store-compliance](https://github.com/mjmirza/app-store-compliance/tree/d2156bab9d7189835631c0a99adcc2479d32138d) as an external reference; Kit does not bundle that project's source, documentation or data. The Kit-authored skill is MIT-licensed. The referenced upstream revision uses [OpenRoots Agent License 2.3](https://github.com/mjmirza/app-store-compliance/blob/d2156bab9d7189835631c0a99adcc2479d32138d/LICENSE), with separate conditions for its use.

Enabling this category only projects the skill. It does not clone upstream, install dependencies, register global hooks, access store accounts or submit an app. To use the optional upstream scanner, provide a separate checkout under its applicable license and its Bash/Python dependencies; on Windows that requires a compatible Bash environment. Scanner findings still need evidence review and current policy verification.

## Project-specific boundaries

These components are reusable sources, not a declaration of project policy. In particular, selecting Alibaba Cloud discovery or Lark does not copy LingoFly account, region, project, incident, or tracker conventions into another project. Projects decide their own credentials, authorization, account setup, and operating procedures.
