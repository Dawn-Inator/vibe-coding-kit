# Codex Task Progress

0.7.6 在返回窗口时，对已验证且已有内存快照的聊天和项目范围立即显示上次内容，并在需要时后台重新读取权威数据。后台出错时保留上次显示，但不表示它仍是最新数据；不受支持、不可信、已移动或已禁用的上下文不会继承其他范围的快照。面板仅在上下文匹配时恢复任务、历史或心跳标签及相关展开选择。五秒轮询独立运行，五秒快照租期避免重复工作，待读取仍保留快速后续请求。没有快照的冷启动仍须首次读取，因此不保证所有情况都能立即或在一秒内显示。任务模型和写入仍以权威数据为准，不新增磁盘或浏览器存储。

这是 [Ezra-Y/codex-goal-progress](https://github.com/ezra-y/codex-goal-progress) 的私有衍生版本，保留原 Git 历史、MIT 许可证和上游署名。当前版本为 0.9.2。0.6.0 引入了不兼容的原生专用界面：受支持 UI 为只读 MCP App；CDP 注入面板、自定义 Dock 启动器及其管理命令均已退役。旧版安装必须先用旧安装器安全卸载，再安装此版本。新版安装器发现旧版标记时会停止，不覆盖旧安装。

从 0.8.1 起，元数据和资源列表公布带发布版本的 URI；0.9.2 公布 `ui://codex-task-progress/panel-0.9.2.html`。旧 `panel-v1.html` 和兼容的已发布 semver 别名仍可用于兼容读取，返回当前服务端的面板 HTML。旧服务器不认识未来版本 URI 时会明确拒绝，不会静默返回旧页面。0.7.7 曾公布稳定的 `panel-v1.html` URI。可通过渲染元素的 `data-task-progress-version` 确认实际前端版本；如有需要，重新进入聊天或切换聊天以刷新宿主 catalog，不要重启 Codex。用户曾确认 0.8.1 的新版原生界面正常加载，但后续画面又显示旧界面；宿主表现尚未完全解决。

0.7.8 通过共享 Kit 读取器支持显式选择的 Heartbeat 账本及其头文件／历史文件对，合计上限为 32 MiB。普通发现仍有单独的安全边界；显式恢复直接验证所请求的项目账本，不依赖全范围扫描。Kit 拥有规范写入器和记录，面板仍为只读。迁移正在使用的账本需要先停止所有写入并保留历史；安装和面板读取不会静默迁移。实际迁移及原生面板数据须分别验证。

0.7.9 精简任务模块下方的常规来源详情，并将 Project Heartbeat 校验提示整理为紧凑的审计摘要，呈现真实风险。原生面板和数据的实际表现仍须单独验证。

可选的独立 `task_root: <Items ID>` 从现有 Items 登记表选择 tracking 根节点及其关联后代用于任务投影；未设置时仍使用全部 Items。围栏代码块中的示例会被忽略；仅有围栏示例时仍使用全部 Items。无效或空的活动声明、重复或冲突的声明，以及缺失、非 tracking 或循环的根节点均 fail closed。生产者从权威来源派生同一登记表中的所选 Items，不要手工维护另一份业务计数或创建第二个存储。

0.8.2 的 Running 和 List 指标去掉大卡片边框，改用紧凑圆环和数字。圆环用于标记数量，不代表任务完成百分比。未知值显示灰环和 —。Heartbeat 时间指标不显示百分比。新样式仍待原生宿主验证。

0.9.0 使用无框分配圆环，将记录的运行中 agent 数与明确的 agent 计划比较。分子来自 Heartbeat 审计后的观测，审计前后变化作为辅助信息；列表数量不是分母。计划或观测缺失、不匹配、分母为零或运行数超过计划时，不绘制误导性的进度弧；未知显示灰环。这是带时间的观测，不是 Desktop 实时计数。原生入口迁移到 `task_progress_dashboard`；`task_progress_panel` 仍作为 model-only 只读兼容入口。原生渲染和迁移仍须在宿主中验证。

Heartbeat 后台刷新待完成时，仅在父线程和任务周期匹配的情况下保留已验证的 ready 分配结果。无记录、终止错误或不匹配时仍显示未知。新原生入口仍待实际宿主验收。

0.9.2 统一了 Archive 标题与行项目的悬停命中区域内缩边界、间距和圆角。归档数据与逻辑未变。此版本的原生界面仍待实际宿主验收。

## 0.8.0 版本

0.8.0 默认展示 Subagents；可切换到 Registered tasks，并保留父目标的完整分母。顶部数量和各 agent 进度来自 Kit 规范化快照。仅当 Heartbeat 来源与当前聊天相关时才展示其记录数量及观察时间；这不是实时计数。独立 app-server 无法证明 Desktop 中哪些 agent 正在实时运行。子 agent 自己的规范清单可提供其进度；数据缺失、已绑定、来源不确定或工作目录不同时保持未知（—），不推为 0% 或 100%。不创建额外状态存储。面板使用可用高度，中间列表滚动，页脚留在底部。任务展示隐藏内部收尾检查点，但完成判定条件不变。加载更多与归档控件采用统一样式。本地独立 fixture 预览存在，但不是生产数据。

## 原生面板

原生 MCP App 使用 Codex Desktop 的 MCP Apps 入口和可选 `enable_mcp_apps` 功能。Kit 安装或复用插件与 Helper 时不会询问 Dock 入口。安装前用 `codex features list` 检查宿主功能；如果尚未启用且用户选择使用原生 MCP Apps，需显式运行 `codex features enable enable_mcp_apps`。安装器不会修改宿主设置；无法确认原生 MCP 支持或功能未启用时会返回 `NATIVE_MCP_SETUP_REQUIRED`。按 Codex 要求重新打开或新建聊天，然后在普通聊天中确认面板和数据实际可见。插件已注册、构建成功或 Helper 健康，都不能证明宿主显示了界面；不支持该功能的宿主不保证可见。

每次请求时，原生 App 解析受支持宿主的当前线程身份，再通过本机 Helper 和 Kit 规范 API 读取对应用户的任务、历史记录和项目 Heartbeat，并排除 subagent 与 ephemeral 线程。任务写入仍受 Hook 与 turn 证明保护。已有的 Codex 原生 Goal 模型 API、记录格式和兼容性继续保留；插件不创建 Goal，也不提供自定义 Goal 界面。

任务数据遵循 Kit 规范记录。原生面板展示已登记清单、记录状态与证据、分页历史，以及只读项目 Heartbeat。Heartbeat 仅用于观察，不会创建调度或写入账本。历史面板使用有界摘要投影（单次源输入最多 512 KiB，每条摘要最多 512 个 Unicode 字符），并保留完整规范 Markdown 路径；底层 Kit 记录不会被截断或改写。

Heartbeat 视图展示审计前和重新拆分／派发后记录的实际活跃子 agent 数、观察时间和证据，以及已审计的阻塞任务和是否需要 Owner 介入；未知时显示未知。这些是快照，不是实时计数。十类审计行和完整 Items 登记表仍保留在规范账本中供审计，不作为主视图。首次使用或旧记录没有生产者提供的快照时显示未知，不能推测过去的活动。监督方通过 Kit 心跳写入器记录快照，插件只读取。

0.6.6 的项目 Heartbeat 摘要使用两张白色描边时间卡片。左侧卡片显示最近一次记录的日期；下一时间卡片显示实际时间，未知时显示“未记录”。卡片不显示文件名页脚，也不共享灰色背景，并适配宿主主题、RTL 方向和窄面板。

0.6.5 的签名生产版 Helper 使用内嵌的匹配面板资源，即使聊天仍使用旧 launcher 根路径也使用该 Helper 自身版本匹配的面板 HTML。源码运行时继续使用固定的 runtime 资源；内嵌仅适用于生产 SEA。更新后若原生面板仍显示旧样式，请按上文重新加载聊天；仅关闭并重新打开面板标签可能无法触发宿主刷新。不要重启 Codex。实际面板可见性和数据须与 Helper 健康状态分别验证。

请按[安装指南](INSTALL-FOR-AI.md)操作。插件要求 Apple Silicon macOS、支持 MCP Apps 的 Codex Desktop；开发与构建要求 Node.js 22.12+ 和 pnpm 11。本地发布签名复用已配置身份；签名不会授予 TCC 权限，也不会自动授权受保护目录。

## 任务生命周期

插件 Helper 会在普通本地任务写入时启用 `lifecycle: true`；其他 Kit 客户端可关闭 API opt-in 以兼容 v3。已有 schema v3 历史仍可读取并原样保留；只读 `task_progress_get` 不会为旧任务伪造已关闭状态。受管理任务有一个显式收尾检查点：只有分支工作、合并和推送已实际完成或经核实不适用，且附有可验证引用、剩余工作为零、Owner 待办为零时才能完成。清单达到 100% 不等于任务关闭；没有供人工点击的 Finish 按钮。执行状态仍单独表示工作进行中或未知。

已完成任务收到新范围后，使用当前 revision 调用 `task_progress_rescope` 开始新周期；不要将旧已完成节点带入新范围。若调用方重复提交旧范围，Kit 会移除完全未变的目标和条目，只保留实际新增或变更的工作；变更目标中不复制旧已完成子项。没有新增工作时拒绝新周期。周期中途调整范围时，输入包含所有保留目标；移除的节点保留为 cancelled，新增或取消都可能改变分母并使本周期进度回退。完成后开始的新周期按新范围重新计算分母，旧周期作为只读归档留在任务历史中。`task_progress_archive` 分页读取归档摘要和详情；归档周期默认按需加载，当前 subtasks 单独显示。不改写原始历史，也不创建独立归档存储。只读 Heartbeat 来源没有正式周期 API，因此其生命周期完成与归档不可用，不能推测，也不能回退到 dormant 的本地任务。Native Goals 保持不变。

## 数据与兼容性

本机 Helper 由现有 launchd 服务管理。MCP 请求经 stdio 服务到 Helper，再按操作权限读取或写入 Kit 规范记录。Kit 的可选 `task-progress` 类别安装或复用原生插件；不再提供单独的启动器或 Dock 选择。

现有任务和 Heartbeat 格式保持兼容。已有 schema v3 任务事件仍可读取并保留；显式启用的生命周期事件使用现有任务日志中的 schema v4。归档摘要和详情是从历史派生的只读视图，不是新存储。已有原生 Goal API 和 v1/v2 原始 Goal 记录仍可读取。历史源数据予以保留；简短摘要只是有界展示投影。再分发时请保留衍生版本的上游 Git 历史、许可证和署名。
