# Codex Task Progress

0.7.5 为 GET 的来源发现设置 200 毫秒响应预算。发现尚未完成时，响应不会暴露本地任务；后续请求共享正在进行的发现过程。原生面板以有界、不重叠的后续请求获取就绪结果，隐藏或销毁后停止重试。写入仍执行完整的来源权威性检查，内部宿主读取也会复用已验证的会话身份。首次内容显示时间取决于宿主和数据可用性，冷启动项目无法保证在一秒内显示。

这是 [Ezra-Y/codex-goal-progress](https://github.com/ezra-y/codex-goal-progress) 的私有衍生版本，保留原 Git 历史、MIT 许可证和上游署名。当前版本为 0.7.5。0.6.0 引入了不兼容的原生专用界面：受支持 UI 为只读 MCP App；CDP 注入面板、自定义 Dock 启动器及其管理命令均已退役。旧版安装必须先用旧安装器安全卸载，再安装此版本。新版安装器发现旧版标记时会停止，不覆盖旧安装。

0.6.2 引入不可变 MCP UI resource，并使用唯一发布版本常量生成版本化 URI。自 0.6.7 起，兼容的旧版 Heartbeat 面板地址（包括旧版 `panel-v1` 和 0.6.3 地址）会返回同一份当前内嵌 HTML；对外只公布当前发布版本的 URI。如果更新后原生面板仍显示旧样式，请重新打开聊天，或切换到另一个聊天再切回来，让宿主刷新 MCP catalog/resource。仅关闭并重新打开面板标签可能无法触发刷新。不要重启 Codex。这些资源更新不改变认证、任务权限、规范数据格式或 Kit API。

## 原生面板

原生 MCP App 使用 Codex Desktop 的 MCP Apps 入口和可选 `enable_mcp_apps` 功能。Kit 安装或复用插件与 Helper 时不会询问 Dock 入口。安装前用 `codex features list` 检查宿主功能；如果尚未启用且用户选择使用原生 MCP Apps，需显式运行 `codex features enable enable_mcp_apps`。安装器不会修改宿主设置；无法确认原生 MCP 支持或功能未启用时会返回 `NATIVE_MCP_SETUP_REQUIRED`。按 Codex 要求重新打开或新建聊天，然后在普通聊天中确认面板和数据实际可见。插件已注册、构建成功或 Helper 健康，都不能证明宿主显示了界面；不支持该功能的宿主不保证可见。

每次请求时，原生 App 解析受支持宿主的当前线程身份，再通过本机 Helper 和 Kit 规范 API 读取对应用户的任务、历史记录和项目 Heartbeat，并排除 subagent 与 ephemeral 线程。任务写入仍受 Hook 与 turn 证明保护。已有的 Codex 原生 Goal 模型 API、记录格式和兼容性继续保留；插件不创建 Goal，也不提供自定义 Goal 界面。

任务数据遵循 Kit 规范记录。原生面板展示已登记清单、记录状态与证据、分页历史，以及只读项目 Heartbeat。Heartbeat 仅用于观察，不会创建调度或写入账本。历史面板使用有界摘要投影（单次源输入最多 512 KiB，每条摘要最多 512 个 Unicode 字符），并保留完整规范 Markdown 路径；底层 Kit 记录不会被截断或改写。

Heartbeat 视图展示审计前和重新拆分／派发后记录的实际活跃子 agent 数、观察时间和证据，以及已审计的阻塞任务和是否需要 Owner 介入；未知时显示未知。这些是快照，不是实时计数。十类审计行和完整 Items 登记表仍保留在规范账本中供审计，不作为主视图。首次使用或旧记录没有生产者提供的快照时显示未知，不能推测过去的活动。监督方通过 Kit 心跳写入器记录快照，插件只读取。

0.6.7 的严格只读资源模板会接受 0.5.16 至当前版本之间兼容的旧版 Heartbeat 面板地址，并返回当前匹配的面板 HTML；对外只公布当前发布版本的 URI。升级后如果宿主仍保留旧 URI或显示旧间距，请重新打开聊天，或切换到其他聊天再切回来，让宿主刷新 MCP catalog/resource；仅关闭并重新打开面板标签可能无法触发刷新。不要重启 Codex。实际原生宿主验收仍待验证。

0.6.6 的项目 Heartbeat 摘要使用两张白色描边时间卡片。左侧卡片显示最近一次记录的日期；下一时间卡片显示实际时间，未知时显示“未记录”。卡片不显示文件名页脚，也不共享灰色背景，并适配宿主主题、RTL 方向和窄面板。

0.6.5 的签名生产版 Helper 使用内嵌的匹配面板资源，即使旧聊天仍使用旧 launcher 根路径也不会读取旧面板 HTML。源码运行时继续使用固定的 runtime 资源；内嵌仅适用于生产 SEA。更新后若原生面板仍显示旧样式，请按上文重新加载聊天；仅关闭并重新打开面板标签可能无法触发宿主刷新。不要重启 Codex。实际面板可见性和数据须与 Helper 健康状态分别验证。

## 安装与验证

请按[安装指南](INSTALL-FOR-AI.md)操作。插件要求 Apple Silicon macOS、支持 MCP Apps 的 Codex Desktop；开发与构建要求 Node.js 22.12+ 和 pnpm 11。本地发布签名复用已配置身份；签名不会授予 TCC 权限，也不会自动授权受保护目录。

分别记录包/构建检查、Helper `doctor` 与 `verify`、插件注册，以及受支持宿主中的原生 UI 可见性和数据验证。宿主功能变更后可能需要新建或重新打开聊天。不能由命令成功推断 UI 已可见。

## 任务生命周期

插件 Helper 会在普通本地任务写入时启用 `lifecycle: true`；其他 Kit 客户端可关闭 API opt-in 以兼容 v3。已有 schema v3 历史仍可读取并原样保留；只读 `task_progress_get` 不会为旧任务伪造已关闭状态。受管理任务有一个显式收尾检查点：只有分支工作、合并和推送已实际完成或经核实不适用，且附有可验证引用、剩余工作为零、Owner 待办为零时才能完成。清单达到 100% 不等于任务关闭；没有供人工点击的 Finish 按钮。执行状态仍单独表示工作进行中或未知。

已完成任务收到新范围后，使用当前 revision 调用 `task_progress_rescope` 开始新周期；不要将旧已完成节点带入新范围。若调用方重复提交旧范围，Kit 会移除完全未变的目标和条目，只保留实际新增或变更的工作；变更目标中不复制旧已完成子项。没有新增工作时拒绝新周期。周期中途调整范围时，输入包含所有保留目标；移除的节点保留为 cancelled，新增或取消都可能改变分母并使本周期进度回退。完成后开始的新周期按新范围重新计算分母，旧周期作为只读归档留在任务历史中。`task_progress_archive` 分页读取归档摘要和详情；归档周期默认按需加载，当前 subtasks 单独显示。不改写原始历史，也不创建独立归档存储。只读 Heartbeat 来源没有正式周期 API，因此其生命周期完成与归档不可用，不能推测，也不能回退到 dormant 的本地任务。Native Goals 保持不变。

## 数据与兼容性

本机 Helper 由现有 launchd 服务管理。MCP 请求经 stdio 服务到 Helper，再按操作权限读取或写入 Kit 规范记录。Kit 的可选 `task-progress` 类别安装或复用原生插件；不再提供单独的启动器或 Dock 选择。

现有任务和 Heartbeat 格式保持兼容。已有 schema v3 任务事件仍可读取并保留；显式启用的生命周期事件使用现有任务日志中的 schema v4。归档摘要和详情是从历史派生的只读视图，不是新存储。已有原生 Goal API 和 v1/v2 原始 Goal 记录仍可读取。历史源数据予以保留；简短摘要只是有界展示投影。再分发时请保留衍生版本的上游 Git 历史、许可证和署名。
