# HTML architecture

Use [assets/starter.html](assets/starter.html) as a reference for stage scaling, navigation, accessibility state, and deterministic export. Before coding, read the complete selected library recipe, or establish the custom or user-reference design system, and plan the motion. Then implement only the representative pages authorized under [style discovery](references/style-discovery.md). A working controller does not authorize expanding an unapproved direction. Its two sample pages are deliberately static and unthemed: reuse mechanics, not their layout, type scale, controls styling, or an invented universal entrance animation. Build the actual composition and graphic system from the selected design. Inline [viewport-base.css](viewport-base.css) before single-file delivery, or package it with the HTML; the starter's relative CSS path must be adjusted when copied.

Default: a 1920×1080 `.deck-stage` inside `.deck-viewport`, scaled uniformly to fit, with letterboxing on other viewports. Respect an existing deck or requested aspect ratio; update CSS dimensions, scaling constants, and export dimensions together. Keep controls outside the authored stage and leave safe space for them. Do not reflow a fixed-stage deck on phones; explain the resulting small portrait text.

Use `.slide.active` / `.slide.visible` with visibility, opacity, and pointer-events. Do not switch slides with display toggles that later layout rules can override. Inactive slides must be inert and hidden from assistive technology. Ignore navigation shortcuts inside interactive/editable controls. Move focus out of a slide before deactivating it.

Expose `window.renderSlide(index, { exportMode: true })` for deterministic export. It must stop all clocks and stale callbacks, select exactly one slide, explicitly render that scene at its stable final state (including function-driven SVG/Canvas), show all intended reveals, hide temporary overlays/controls, and resolve after rendering. Cancelling an animation alone does not paint its final frame. Navigation must cancel previous scene work before starting the next one. Keep normal interactive behavior separate from export behavior. The bundled exporter requires this hook rather than guessing how arbitrary deck controllers work.

For time/progress-driven graphics, read [function animation](references/function-animation.md) and provide a deterministic `render(progress)` per meaningful scene. Do not assign a nonzero transition duration to every element in reduced-motion CSS: the default transition property is `all`, which can animate visibility/opacity changes and capture overlapping slides even after clocks stop. Reduced motion must stop existing frame loops and immediately paint the stable state, including when the preference changes during playback.

Use [animation-patterns.md](animation-patterns.md) for effect ideas and [motion direction](references/motion-direction.md) for sequencing. Add editing, presenter notes, swipe, or step controls when useful; do not promise persistence or file saving until implemented and checked. Essential content stays visible under reduced motion.

Bundle images and licensed fonts or embed them when practical. No build dependencies does not imply offline operation: remote fonts, media, and scripts require network access. Adapt template fonts and palettes to the user’s actual constraints.

For a complete composed, function-animated deck rather than starter mechanics, see the optional [Delivery Practice recipe and runnable example](references/delivery-practice.md). Select it only when its visual grammar fits the content and adapt the actual scenes.
