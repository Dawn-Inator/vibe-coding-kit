# Codex Task Progress

基于 [Ezra-Y/codex-goal-progress](https://github.com/ezra-y/codex-goal-progress) 的独立私有改造，保留原始 Git 历史、作者归属和 MIT 许可证。

0.4.3 在聊天顶部常驻任务面板并预留布局空间，避免覆盖正文，支持展开子任务、查看完成证据、浮动布局和分页历史。总进度按有效必做清单项计算，新增任务可以使进度回退；没有清单时显示空闲状态。模型通过 task_progress_* 工具维护记录，无需创建原生 Goal。

发现并确认关联 Kit 心跳台账后显示心跳模块，提供最近巡检、Items、审计与认证结果及历史。关联后，面板任务清单直接投影 Kit 的 Items，来源只读并保持权威；插件不会另建并行清单或写入本地事件。更新应走原始台账工作流，主动解除绑定后才恢复休眠的本地历史。共享 Kit 负责发现、状态映射、进度与周期策略；来源失效时保留错误/过期状态并阻止本地写入。读取不创建定时器、不修改台账，也不把插件在线当成巡检。

完整开发和接口说明见 [README](README.md)，本地构建安装流程见 [INSTALL-FOR-AI](INSTALL-FOR-AI.md)。私有衍生版应从本仓库构建，不使用原作者的发布包。首次启用本地调试连接可能需要重启 Codex，必须先征得用户同意。

浏览器模拟环境验证与实际 Codex 中的验收必须分别报告。进度语义更新依赖当前模型在任务里调用插件工具；进度条不会根据时间、Token 或命令数量自动猜测完成率。

调试连接已建立后，可构建新版并运行 `./install.sh` 热更新后台与面板，无需重启 Codex。新增 MCP 工具需要重新打开受影响的聊天加载。大型心跳台账采用摘要与分页，不一次传输全部历史。

完成口径：面板只统计已登记清单，不声称知道整个任务的剩余范围。执行状态独立观察；清单勾满但仍在执行、等待或状态未知时，不显示100%或满格进度条。空闲也不代表整体交付完成。模型仍需及时登记新增和收尾工作。

0.4.3 将普通任务记录存到聊天工作目录的 `.workspace/codex-task-progress/`，使用 Kit 统一路径接口。任务历史在 `tasks/v3/<聊天哈希>/`，心跳绑定与缓存在 `sessions/<聊天哈希>/heartbeat/`。旧记录按聊天复制迁移并保留原文件，冲突不会静默覆盖。原始心跳台账不移动；后台程序、通信文件和日志仍位于系统目录。
