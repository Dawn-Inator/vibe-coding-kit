# Codex Task Progress

基于 [Ezra-Y/codex-goal-progress](https://github.com/ezra-y/codex-goal-progress) 的独立私有改造，保留原始 Git 历史、作者归属和 MIT 许可证。

0.4.4 在聊天顶部常驻任务面板并预留布局空间，避免覆盖正文，支持展开子任务、查看完成证据、浮动布局和分页历史。总进度按有效必做清单项计算，新增任务可以使进度回退；没有清单时显示空闲状态。模型通过 task_progress_* 工具维护记录，无需创建原生 Goal。

面板自动显示当前项目的 Heartbeat（若可用），包括来源路径、状态、审计详情和只读说明，不要求用户选择台账。项目 Heartbeat 展示与聊天任务权威分开：只有与当前任务关联的结构化 Kit 记录才会成为 `taskSource` 并替代聊天清单；无关的项目台账不会覆盖本地任务进度。读取不创建定时器、不修改台账，也不把插件在线当成巡检。

完整开发和接口说明见 [README](README.md)，本地构建安装流程见 [INSTALL-FOR-AI](INSTALL-FOR-AI.md)。私有衍生版应从本仓库构建，不使用原作者的发布包。首次启用本地调试连接可能需要重启 Codex，必须先征得用户同意。

浏览器模拟环境验证与实际 Codex 中的验收必须分别报告。进度语义更新依赖当前模型在任务里调用插件工具；进度条不会根据时间、Token 或命令数量自动猜测完成率。

调试连接已建立后，可构建新版并运行 `./install.sh` 热更新后台与面板，无需重启 Codex。新增 MCP 工具需要重新打开受影响的聊天加载。大型心跳台账采用摘要与分页，不一次传输全部历史。

完成口径：面板只统计已登记清单，不声称知道整个任务的剩余范围。执行状态独立观察；清单勾满但仍在执行、等待或状态未知时，不显示100%或满格进度条。空闲也不代表整体交付完成。模型仍需及时登记新增和收尾工作。

0.4.3 将普通任务记录存到可信聊天工作目录的 `.workspace/codex-task-progress/`，使用 Kit 统一路径接口。普通聊天 History 的权威事件在 `tasks/v3/<thread-sha256>/events.jsonl`；同目录 `snapshot.json` 是可重建快照，不是权威历史。心跳绑定与派生观察缓存按聊天隔离在 `sessions/<thread-sha256>/heartbeat/`，不构成原始心跳台账。原始台账仍由项目配置绑定的路径作为权威来源（例如 `.workspace/task/<session>/heartbeat.md`），插件只读、不迁移。若关联任务来源生效，History 直接读取其绑定台账中的 wake 记录，不另写一份时间线；项目 Heartbeat 卡片可以展示不同来源。旧任务记录按聊天复制迁移并保留原文件，冲突不会静默覆盖。应用支持目录中的 `workspace-storage-index.json` 只保存线程与工作区路径，用于工作目录变化时定位任务历史，不保存时间线或心跳台账。后台程序、通信文件和日志仍位于系统目录。
