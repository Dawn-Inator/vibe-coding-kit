# 健康结论怎么判——这是证据推导出的结论,不是可以手填的状态

| 结论 | 什么情况下能这样判 |
| --- | --- |
| 健康 | 卡片完整且跟实际存储/迁移状态一致;容量、保留、物理设计、所有权、一致性都有当前证据;没有
  任何重评阈值被越过。 |
| 暂定 | 决策已经完整且可以上线,但容量还是有依据的预估,或者运行时的投影/切换证据还没收集完整——要
  写清楚还差哪些证据没验证。 |
| 未知 | 核心输入缺失,或者只是靠命名约定隔离(没有对着真实数据库校验过),或者只证明了当前测试能读写
  ——这种情况下**禁止**说成"目前够用"或"架构健康"。 |
| 不健康 | 放置/日志边界已经被违反,重评阈值已经越过,或者缺少必要的保留/一致性保护。 |

没有实测的行数/写入速率/存储占用/延迟证据时,正确做法是给一个可追溯的"预估+暂定",或者干脆写
"未知"——**"没有证据显示撑不住"不等于"有证据显示健康"**。
