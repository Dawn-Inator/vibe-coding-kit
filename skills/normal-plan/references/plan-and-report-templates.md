## 常用计划模板

````markdown
# <任务名>

## 一图看懂

**目的**:<为什么做 / 用户或业务要达成什么,不写技术>
**做法**:<怎么做、用哪些技术 / 模块>

<文本执行路径图,样例见 references/example-diagram.md>

图例:`[n]` 步骤,`◆` 需拍板,`✓` 验证关卡,`‖` 并行分支,`└─ 红 ─▶` 失败回路。HTML 视图:<路径,或「未触发:原因」>

## 需要你拍板

- <决策 / 未知 + 推荐>;或「无」

## 目标与完成判据

- 目标:<一句话>
- 完成判据:<可判红的命令 / 断言 / 行为>

## 任务与步骤

1. <步骤>
2. <步骤>

- Subagent:<不派原因,或 Wave 表>
- 风险门禁:<风险表,或「无新增质量风险,原因:…」>

## 闭环清单

| 项 | 结论 | 依据 / 命令 | 不适用原因与剩余风险 |
| --- | --- | --- | --- |
| Worktree / base | | | |
| 文档影响 | | | |
| SQL 迁移 | | | |
| 测试 spec 变更 | | | |
| 验证命令 | | | |
| 目标分支与收尾 | | | |
````

## 可选示例:执行完成报告

如果项目希望使用固定的完成报告格式,可以参考下面的模板并按本项目习惯调整。示例中的图使用纯文本;它不是本 kit 强制的报告政策。

采用该模板时,计划与完成报告保持对应关系;具体标题和内容以项目自己的报告要求为准。

````markdown
# 执行完成报告

## 计划 vs 实际

**目的是否达成**:<是 / 否 / 部分 + 一句话依据>

```
[✓] [1] <实际完成的步骤>
│
▼
[✓] [2] <验证关卡及结果>
│
▼
[✓] [3] <收尾结果及完成判据>
```

图例：`[✓]` 完成、`[≈]` 偏差、`[✗]` 放弃、`[…]` 未做；沿用原编号，无计划按实际顺序编号。

计划有 HTML 视图时,在同目录产出 `<plan-name>.recap.html`(同样不进仓库)。

## 偏差

- <偏离计划的地方 + 原因 + 是否需要开发者认可>;无偏差写「无」。图上有 `[≈]` / `[✗]` / `[…]` 节点却没在此说明,报告无效。

## 状态

- 实现候选:<待定 / 通过 / 失败 + 精确 commit SHA>
- 代码验证:<待定 / 通过 / 失败 + 精确 commit SHA>
- 运行验收:<待定 / 通过 / 失败 / 不适用 + 精确 commit SHA>
- 未完成或阻塞:<无,或原因>

## 闭环清单(实际)

| 项 | 实际结果 | 证据 | 未做原因与剩余风险 |
| --- | --- | --- | --- |
| Worktree / 临时分支清理 | 实际 `worktree:begin` / `worktree:end` 命令与终态结果;临时 worktree 与临时分支是否已删除 | 命令输出 / 日志路径 | 未删除:保留路径、分支、失败命令、阻塞原因 |
| 已新建/修改文档 | 路径 + 变更类型(新建 / 修改 / 同步生成) | | 无已新建/修改文档,原因:… |
| 已执行 SQL / migration | 路径、目标环境、自动化入口、结果 | 你项目的迁移执行记录 | 无已执行 SQL,原因:… |
| 测试脚本 / spec 变更 | 路径、变更类型、覆盖目标;bugfix 写逃逸原因与回归覆盖路径 | | 无测试脚本 / spec 变更,原因:…;回归覆盖路径缺失原因:…;剩余风险:… |
| 验证情况 | 实际运行的命令与 pass / fail,以及在哪跑 | 输出摘要 | 未运行:原因和风险 |
| 目标分支和 push 状态 | 目标分支、合并 / push 状态 | push 结果 | |
````

报告每行同样不得只写「无」。验证情况只记录实际跑过 / 没跑的命令,不能替代测试脚本 / spec 变更行。
