# 写计划的硬要求

1. 不写 `TBD`、`TODO`、"按需""完善""处理边界"等占位话;模板尖括号必须全部替换。
2. 闭环清单 6 行全部填写;任何一行不得只写「无」,必须带原因与剩余风险。
3. 不默认跑全量 / 发布级检查;只有用户明确要求或场景确实需要时才写。
4. 数据库变更只走你项目自动化的迁移入口;未执行或缺少验证证据的一律标为待执行,不口头写成已完成。
5. bugfix 不得漏写原自动化覆盖缺口 / 逃逸原因与两层回归覆盖路径;真机冒烟和截图不算自动化测试。
6. 不把临时 worktree 分支当 push 目标;push 的是目标分支,由 `worktree:end` 完成。
7. 执行路径图必须是本次计划的真实执行顺序,节点编号与「任务与步骤」一致,图前「目的 → 做法」两行齐全;
   HTML 视图不得写进仓库。
