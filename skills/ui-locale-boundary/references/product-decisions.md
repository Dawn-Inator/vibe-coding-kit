# Record irreversible or judgment-call product decisions once, in the doc, not per-conversation

Language-scope decisions attract the same well-intentioned suggestion repeatedly: "should we add a
third language while we're in here," "should the internal-only admin tool get localized for
consistency," "can I fix this legal/compliance text's wording since I noticed it's wrong." If your
project has already made an explicit decision on any of these (adding a language is a product
decision requiring content/translation capacity, not a refactor; an internal-only tool used solely by
one team may be deliberately exempt from i18n; legally-reviewed text must never be silently edited by
an automated agent, even to fix an apparent error), write that decision down once, next to this skill,
so it doesn't get re-litigated in every future conversation that touches the area. See your project's
knowledge-artifact-management skill for where owner-decision records like these belong.
