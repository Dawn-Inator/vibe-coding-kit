# Ultra-plan 调研与拆解经验

| 误区 | 正确做法 |
| --- | --- |
| 未点名 ultra-plan 就自动升级 | 用 `normal-plan`,最多建议开发者可以升级 |
| 把项目的长规则原文复制进本 skill 产出的文档里 | 读取源文件,在总体规划里写摘要和路径 |
| 一上来就派十几个调研员,让每个人各自把同一件跨模块的事整套设计一遍(曾经真实出现过 3 种互斥鉴权方案、2 种 URL 前缀、2 种密码存放口径、2 种通知架构同时存在,主 agent 要读完全部摘要才能裁决) | 先做 Phase 0.5 裁决先行,把跨模块决策定死;Phase 1 按平台授权和真正独立的问题选择是否派发,职责收窄为"事实 + 实现路径",不得重开已裁决事项 |
| 模块文档写成大纲/概要 | 写到"零参考可执行"的详细程度,不留占位话;文件级事实引用调研报告路径,不整段复制 |
| ≥2 个模块共享接口却没先冻结契约,Wave 并行后前后端字段/URL 对不上 | 先写死 `99_跨模块契约.md` 再开 Wave |
| 直接执行只跑第一波就停下汇报 | 授权后连续执行全部 Wave,除非真实阻塞或触发额度阈值 |
